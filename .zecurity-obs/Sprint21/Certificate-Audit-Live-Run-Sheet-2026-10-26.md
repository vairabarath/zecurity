## Observations (not stage failures)

Tracked as F44–F47 in `Sprint20/path.md`; fix note: [[Sprint20/Fixes/Fix14-Shield-Stream-Reconnect-Sessions]] (O1 = F44 + F45, O3 = F46, O4 = F47; O2 = F38, fixed by Fix 13).

- **O1 — a shield cert renewal breaks open sessions through that shield.** At 05:50:05 the shield renewed and reconnected its Control stream; the open session stalled at 05:50:06 (no data, no EOF) and timed out (`session-ended-at-shield-renewal.log`). New connections worked at once. Cause in code: tunnels ride the shield's Control stream; the shield builds a fresh `TunnelHub` per stream (`shield/src/control_stream.rs`), and on disconnect the connector's `unregister_shield` drops only the send channel, never the shield's relay sessions (`connector/src/agent_tunnel.rs` ~83), whose `RelaySession` keeps the old stream's sender. Present on `main`, `fixed-pendings` and `sprint20/fix13-revocation-low-findings` (since `372744dd` / `d935844b`). In production TTLs this hits about once per 5 days per shield, and on any Control stream reconnect.
- **O2 — revoked connector's relay selector keeps retrying** (`Relay rejected Connector registration: connector is revoked`, every few seconds). This is F38; its fix is on `sprint20/fix13-revocation-low-findings`, not on this branch.
- **O3 — the shield keeps redialling a revoked connector** about every 2.4 s while it is its only connector.
- **O4 — a suspended admin's still-valid access token kept working** for admin GraphQL (`createGroup` at 05:55:17 and 05:55:44 succeeded while suspended). Bounded by the 15 min access-token lifetime.
- **F32** (revoked relay keeps reconnecting): not exercised; no relay was revoked in this run.

## Deviations from the runbook

1. **Lab topology:** controller, relay, client and both proxies on 192.168.1.164; connector on inkyank; shield on manoj (nika went offline; its first shield `cl-shield` was revoked and deleted); B/F second agents on udaya. Agents used `192.168.1.164:9090/8080/18080/18081`.
2. **Relay advertisement:** a LAN relay is only offered to connectors with `RELAY_DEV_ALLOW_PRIVATE_ADDR=true`; the controller was restarted with it at 05:14:30 (first log kept as `controller-0-before-private-relay-flag.log`). Relay ran with `CONTROLLER_ADDR=192.168.1.164:9090`, `RELAY_IP_SANS=192.168.1.164,127.0.0.1`.
3. **No local `psql`:** queries ran through `docker exec ztna_postgres psql`. The runbook's G4 query uses `c.workspace_id`, which works.
4. **grpcurl:** `connector/v1/connector.proto` imports `proto/client/v1/client.proto`, so `asconn … -import-path proto -proto connector/v1/connector.proto` fails to parse; used `-import-path . -proto proto/connector/v1/connector.proto`.
5. **`buf generate`:** must exclude `.worktrees` (duplicate symbols); ran `buf generate --exclude-path .worktrees --exclude-path .localdev`.
6. **Workspace re-creation:** workspace and admin recreated through the controller's own sign-up provisioning path, and the admin UI/client signed in through a local test identity provider; tokens were minted the same way the admin detail pages do (`POST /api/{connectors,shields}/{id}/token`).
7. **Protected resource:** a TCP echo on manoj:5555 instead of `ssh` (keeps lab SSH out of the client ACL); the long-lived session is a 1 Hz ping client (`session-*.log`).
8. **Stage G order:** suspend → G1 → reactivate → G3 → suspend → G2 → reactivate, because `logout` wipes the device's local state and would make G3 untestable. Policy change = `createGroup` (it calls `NotifyPolicyChange`).
9. **Stage H before G**, to keep a shield renewal (O1) out of the H session window.
10. **Client daemon:** `zecurity-client logout` stops the daemon; restarting it needed `sudo systemctl start zecurity-client`.
11. **Logs:** nika's first `shield.log` is lost (host offline). Client login logs have the local sign-in URL lines redacted.
