# Phase 1 — Database / Migration

> Depends on nothing — Day 1. Additive DDL; no runtime path reads it yet → zero risk to live auth.
> Full spec: [[PENDING-15-Durable-Outbox-Infrastructure]] §1. Copy the schema verbatim — do not
> invent a different one.

## Goal

Stand up `outbox_events` with the four-state lifecycle and every index PENDING-15 §1 requires, so
later phases have their storage.

## Steps

- [x] **M18-1** `outbox_events` table with exactly these columns (from PENDING-15 §1):

```sql
CREATE TABLE outbox_events (
    id              UUID        PRIMARY KEY DEFAULT gen_random_uuid(),
    event_type      TEXT        NOT NULL,
    workspace_id    UUID        NOT NULL REFERENCES workspaces(id) ON DELETE RESTRICT,
    user_id         UUID        REFERENCES users(id) ON DELETE SET NULL,
    correlation_id  UUID        NOT NULL,
    payload         JSONB       NOT NULL,
    status          TEXT        NOT NULL DEFAULT 'pending'
                        CHECK (status IN ('pending', 'processing', 'done', 'failed')),
    retry_count     INT         NOT NULL DEFAULT 0,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    next_attempt_at TIMESTAMPTZ DEFAULT NOW(),
    lease_id        UUID,
    claimed_at      TIMESTAMPTZ,
    last_error      TEXT
);
```

- [x] **M18-1** three required indexes (PENDING-15 §1):

```sql
CREATE INDEX idx_outbox_claim
    ON outbox_events (status, next_attempt_at, retry_count)
    WHERE status IN ('pending', 'failed');

CREATE INDEX idx_outbox_workspace_event
    ON outbox_events (workspace_id, event_type);

CREATE INDEX idx_outbox_processing
    ON outbox_events (status, claimed_at)
    WHERE status = 'processing';
```

- [x] **M18-1b** workspace-deletion handling — hard workspace deletion is **rejected** while any
  outbox rows remain; an explicit, audited retention/archive operation must resolve or archive
  outstanding events first. A committed outbox event must never disappear implicitly through
  cascade deletion. PENDING-15 defines no automatic deletion of durable events.

## Rules

- `workspace_id` NOT NULL + `ON DELETE RESTRICT` — never `CASCADE`. Workspace deletion must resolve
  outstanding events explicitly.
- `correlation_id` is generated by the originating service and passed to `Enqueue`; the outbox
  never replaces it.
- `claimed_at` is the lease timestamp; `updated_at` is a general row-update timestamp — do not
  overload it.
- `last_error` is bounded to **4096 bytes** before persistence (enforced in the store/processor,
  not the schema).
- Do **not** create a `dedupe_key` column or any global deduplication rule — PENDING-15 does not
  impose one.
