# Sprint 18 — Platform Durable Outbox Infrastructure (PENDING-15)

> **Read this before writing a single line of code.**
> Source of truth: [[PENDING-15-Durable-Outbox-Infrastructure]] (the PENDING that defines this
> sprint's design). This sprint implements **only** the reusable platform outbox; it does **not**
> implement SCIM (ADR-025 / Sprint 17), identity lifecycle, or device lifecycle business logic
> (PENDING-13). ADR-025 stays untouched.
> Branch: `pending-15-outbox-plan`.

## Sprint Goal

Give the controller a **durable, transactional, retrying delivery layer** between an identity
decision and its asynchronous side effects. Today side effects are inline or fire-and-forget —
no persistence, no retry, no delivery guarantee. ADR-025 §5 requires that device-trust
side-effects (e.g. `device.trust.revoke.requested`) be delivered through a durable outbox with
retry and observability. This sprint builds that infrastructure.

```text
BEFORE                                          AFTER
------                                          -----
identity mutation commits; async side effects   identity mutation + audit + outbox event commit
are inline or fire-and-forget (no persistence,   atomically in ONE tx; a background processor
no retry, no delivery guarantee)                 durably delivers events at-least-once with
                                                 retry + backoff + crash/lease recovery
```

The outbox is **provider-independent**: it knows nothing about SCIM, Okta/Entra, or devices. It
provides enqueue / claim / dispatch-via-registered-handler / complete / fail / reap only.
Event-specific handlers are registered by their owning subsystem (PENDING-13 for device events,
ADR-025 for lifecycle events) — not by this sprint.

## Key Design Decisions

| Decision | Detail |
|----------|--------|
| Migration | `033_outbox_events.sql` — next available after `032` (matches PENDING-15 §1 and Sprint 17 M2's plan; `030` was skipped for posture). |
| Four-state lifecycle | `status` CHECK constraint: `pending`, `processing`, `done`, `failed`. |
| Transactional enqueue | `Enqueue(ctx, tx, evt)` inserts inside the **caller's** `pgx.Tx` — commits/rolls back with the identity mutation. No event loss after COMMIT, no orphans after ROLLBACK. |
| Concurrency-safe claiming | Single atomic statement: candidate CTE + `FOR UPDATE SKIP LOCKED` + `UPDATE ... RETURNING`; unique `lease_id` + `claimed_at` per claim; deterministic `ORDER BY next_attempt_at, created_at`; `LIMIT` bounds the batch. |
| Lease semantics | `MarkDone`/`MarkFailed` must match `id` **and** `lease_id` **and** `status='processing'`; zero affected rows = stale/lost lease. A stale worker affects nothing. |
| Delivery guarantee | **At-least-once.** Handlers must be idempotent; exactly-once external effects are the handler's responsibility, never the outbox's. No `dedupe_key`-style global suppression. |
| Retry / backoff | `MarkFailed` → `retry_count++`, `next_attempt_at = NOW() + backoff(retry_count)`, `status='failed'`, `last_error` recorded. Exponential backoff `min(5m, 2^retry_count * base)` with jitter; clock and jitter injectable for deterministic tests. |
| Max retries | `OUTBOX_MAX_RETRIES` default **100**, validated `1..1000`. Exhausted events stay `failed`, permanently ineligible, **never silently discarded**. |
| Crash / lease recovery | Reaper resets `processing` events with `claimed_at <= NOW() - lockWindow` to `failed` (+1 retry, backoff, lease cleared). **Lease-aware:** only transitions when the stored `lease_id` still equals the expired lease it identified. |
| Processor defaults | Poll 1s (bounds 100ms–1m), lock window 30s (bounds 5s–1h), reaper 30s (bounds 1s–5m); reaper interval must not exceed the lock window. |
| Generic handler registry | `EventHandler.Handle(ctx, evt) error`; registry keyed by `event_type`. Outbox package contains **zero** event-specific business logic. |
| Unknown event types | Terminal failure: `failed`, `retry_count=max_retries`, `next_attempt_at=NULL`, `last_error="no handler registered for event_type X"`; logged, never retried forever, never silently dropped. |
| Terminal recovery | Explicit operator-only `Recover(ctx, eventID, operatorID, reason, resetRetryBudget)` — never automatic; requires reason + audit; clears lease fields, schedules one attempt; preserves retry count unless `resetRetryBudget` is explicitly authorized. |
| `correlation_id` | Generated by the **originating** service and passed to `Enqueue`; the outbox never replaces it. Preserved through processing and logs. |
| `last_error` | Bounded to **4096 bytes** before persistence; full error goes through existing logging subject to sensitive-data rules. |
| Workspace deletion | `workspace_id` NOT NULL + `ON DELETE RESTRICT`. A hard workspace deletion is rejected while outbox rows remain; an explicit, audited archive/retention operation is required first. No implicit cascade; PENDING-15 defines no automatic deletion of durable events. |
| Observability | Existing Go `log` conventions (matching `controller/internal/identity/`); **no** new observability framework. Metrics deferred to PENDING-10. |
| Startup order | construct outbox → register all handlers → start processor. `go o.Run(ctx, ...)` only after every required handler is registered. |
| Owns handlers? | **No.** Sprint 18 provides the registration mechanism and startup wiring seam only. PENDING-13 registers `device.trust.*` handlers; ADR-025 registers its lifecycle handlers. |

## Acceptance Criteria

### Database
- [ ] `outbox_events` created by migration `033_outbox_events.sql`.
- [ ] Four-state `status` model (`pending` / `processing` / `done` / `failed`).
- [ ] Indexes on `(status, next_attempt_at, retry_count)` for claiming and `(status, claimed_at)` for reaping.
- [ ] `workspace_id` NOT NULL + FK `ON DELETE RESTRICT`; workspace deletion cannot implicitly delete committed events.
- [ ] `lease_id` + `claimed_at` present; `updated_at` is **not** the lease timestamp.
- [ ] `correlation_id` preserved through enqueue/processing/logs; generated by the originating service, never replaced by the outbox.
- [ ] `last_error` bounded to 4096 bytes.
- [ ] `OUTBOX_MAX_RETRIES` validated as a positive bounded config value; default poll/lock/reaper intervals documented and validated.

### Transactionality
- [ ] `Enqueue(ctx, tx, evt)` inserts within the caller's transaction; rollback removes it; commit persists it.

### Concurrency
- [ ] Concurrent workers never receive the same eligible event in the same lease period.
- [ ] Claiming is a single atomic statement (candidate CTE + `FOR UPDATE SKIP LOCKED` + `UPDATE ... RETURNING`).
- [ ] `MarkDone`/`MarkFailed` require `id + lease_id + status='processing'`; stale workers affect zero rows.
- [ ] Reaper resets expired-lease `processing` → `failed` (+retry, backoff, cleared lease) and is lease-aware (never clears a newer lease).
- [ ] Stale-worker race covered: lease A expires, lease B claimed, `MarkDone(lease A)` affects zero rows.

### Reliability
- [ ] Handler failure → `retry_count++` + `next_attempt_at` reschedule; exponential backoff with jitter; exhausted events remain observable `failed`, permanently ineligible, never silently dropped.
- [ ] Abandoned `processing` events become retryable; repeated crash/reap cycles eventually reach `max_retries`.
- [ ] Unknown event types → terminal `failed` (`retry_count=max_retries`, `next_attempt_at=NULL`, `last_error` recorded), logged, not retried forever.
- [ ] Terminal recovery requires explicit operator identity + reason + deliberate requeue authorization; never automatic.

### Processing / Lifecycle
- [ ] Success → `done`; failure → retryable `failed` until exhausted.
- [ ] Processor starts only after all handlers registered; stops cleanly on context cancellation; no goroutine leaks.

## Non-Goals (explicit)

Sprint 18 does **NOT** implement:
- SCIM endpoints, token auth, provider profiles, mappings, user/group provisioning, deprovisioning, conflicts, or `identity.DirectoryService`
- Certificate issuance / renewal / revocation implementation (CRL generation already exists; outbox only triggers it)
- Device lifecycle business logic or device-trust handlers (PENDING-13)
- Okta / Entra / JumpCloud / Keycloak integration
- Device management UI
- New audit-log architecture (the `audit_logs` table is unchanged)
- Kafka / Redis Streams / RabbitMQ or any external message broker — PostgreSQL only
- A new observability framework (metrics deferred to PENDING-10)
